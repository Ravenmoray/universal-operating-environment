# Contributing

UOE is in the public research and architecture phase. **Human contributors and AI-assisted contributors are both welcome.** We especially value evidence, thoughtful critiques of assumptions, small reproducible experiments, and proposals that make the project more rigorous.

## How to participate

- **Explore an idea or ask a question:** use [GitHub Discussions](https://github.com/Ravenmoray/universal-operating-environment/discussions) when enabled; meanwhile open a [research/question issue](https://github.com/Ravenmoray/universal-operating-environment/issues/new/choose).
- **Propose a new architectural direction:** open an [RFC proposal issue](https://github.com/Ravenmoray/universal-operating-environment/issues/new/choose), explain the problem, and seek feedback.
- **Contribute an RFC:** read [the RFC process](docs/rfcs/README.md) and use [the RFC template](docs/rfcs/TEMPLATE.md). Submit a pull request and link its discussion.
- **Submit fixes or code:** use a branch or fork and open a PR with the applicable tests, documentation, provenance and risks.
- **Improve existing work:** comment on an RFC's linked issue or PR, providing concrete counterexamples, sources, test cases or alternatives.

GitHub authentication and appropriate repository permissions are required to publish through GitHub. The repository's instructions do not themselves grant access. People operating AI agents should explicitly authorize any public posts or code submissions made using their accounts. Agents without posting access can prepare proposed Markdown for their operators.

## Quality, openness, and safety

- Search the existing issues, discussions and RFCs to avoid duplicated work.
- Discuss substantial architecture changes before implementation.
- Include tests, evidence and documentation for functional changes.
- Separate observations, interpretations and speculative claims.
- Treat binaries, model outputs and external data as untrusted.
- Only contribute material you have the right to distribute.
- Do not upload secrets, personal data, proprietary binaries or training corpora without explicit redistribution rights.
- Include third-party notices and verify license compatibility.
- Do not produce automated spam, repetitive cross-posts or arguments between agents without a concrete technical contribution.
- Assume RFCs are drafts until maintainers record an explicit decision; public disagreement is welcome.

## AI-assisted contributions

See [AGENTS.md](AGENTS.md) for the agent-specific participation protocol.

When significant work was AI-assisted, note that in the issue or PR and describe what was validated. Identify the accountable submitter when known; don't misrepresent authorship, code review, test coverage or the origin of externally retrieved claims. Human-only participation is equally welcome.

## Licensing contributions

Unless explicitly agreed otherwise before contribution, contributions are provided under the repository's **AGPL-3.0-or-later** license. You retain your copyright when applicable. Existing third-party software retains its original terms; identify reused code and its license clearly.

Contributing does not imply endorsement of every long-range goal.
